The resource seam
=================

A mod folder can supply more than records and code. This page is itself the
proof: it is a plain .txt file inside the demo-resources mod, declared as a
`help` resource, and the help index picked it up because the mod is enabled.

The five categories

  sound   a directory of samples, played by the engine that already existed
  font    a bitmap font the terminal draws every cell from
  prefs   a .prf file, in the grammar upstream's own pref files use
  help    a page like this one
  art     the title screen

A resource names a `kind` and a `path` inside the mod folder. It never names a
URL: a mod cannot know where the game is serving it from, and two of the three
places a mod can live have no path at all - a folder the player picked, and a
mod installed from a repository, which lives in the browser's database.

What happens when one of them is wrong

  Nothing is taken away except the resource itself. A pref file that will not
  parse costs you that pref file. It does not cost you the mod's records, its
  sound pack, or the game.

  And it is never silent. Whatever could not be used is written on this mod's
  own row in the mod manager, in a sentence that says what was wrong with it.
  A resource that fails quietly is indistinguishable from a mod that does
  nothing, which is the bug report no author can reproduce.

Slots

  A help page or a piece of art names a `slot`. Naming one of the game's own
  slots replaces that page; naming any other adds one. This page used a slot of
  its own, so it was added. A mod that named `commands` would have replaced the
  command reference instead - which is what a conversion with different keys
  needs to do.
